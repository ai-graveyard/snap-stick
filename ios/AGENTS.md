# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## What this is

SnapStick (拍立贴) is a native SwiftUI iOS app — originally a port of a Next.js web app (`/Users/ailln/Workspace/github/ai-graveyard/pai-li-tie`). The experience: shoot a photo → the on-device Vision foreground-mask API ("拷贝主体" / subject lift) cuts the subject out of any background → a white die-cut border is painted around it → the print "develops" over ~5s (or instantly if you shake the phone, like flicking a Polaroid) → the sticker drops into a gyroscope-driven physics sandbox where stickers slide and collide as you tilt the phone. History is saved locally on device. UI strings are Chinese.

> **Note:** The original flow cartoonified the photo via a remote AI model (Volcengine Ark 豆包 seedream) and then flood-filled the white background. That AI *render* step was deliberately removed in favor of fully on-device Vision subject extraction, and `ImageCutout.swift` (the white-background flood fill) stays deleted. Doubao has since been **re-introduced in a different, optional role**: the user can bring their own Volcengine Ark API key (设置 → 豆包 API; stored in the Keychain via `KeychainStore`), and `DoubaoAPI.swift` is a minimal Chat Completions client. **Nothing in the capture or classification flow calls it yet** — its only call site is the connectivity test at the bottom of `DoubaoSettingsView` (sends a "hi"). Shooting, cutout, and classification are all on-device and work with no key configured.

## Build & run

```bash
# Compile-check (no signing). There is no local simulator runtime; the app needs a
# physical device anyway (camera + CoreMotion), so this is the normal CI-style check.
xcodebuild -project SnapStick.xcodeproj -scheme SnapStick \
  -destination 'generic/platform=iOS' -configuration Debug \
  CODE_SIGNING_ALLOWED=NO build
```

- Deployment target is recent iOS; run on a real device for camera, gyroscope, and AI features.
- Tests live in `SnapStickTests/` (unit, XCTest) and `SnapStickUITests/` (UI). There is currently only scaffolding, no meaningful tests.

> **Never run, launch, or test the app in the iOS Simulator yourself** (no `simctl boot/install/launch`, no screenshots, no Simulator app). The maintainer does all runtime/visual testing manually on a real device. Your verification stops at the `xcodebuild ... CODE_SIGNING_ALLOWED=NO build` compile check above — do that, then hand back.

## Critical build & concurrency facts

- **File-system-synchronized project group**: the Xcode project uses `PBXFileSystemSynchronizedRootGroup`, so any `.swift` file dropped in `SnapStick/` is auto-compiled. **Do not hand-edit `project.pbxproj` to add files.**
- **`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`**: everything is `@MainActor` by default. Off-main work must be explicitly `nonisolated` (see `VisionCutout` and the camera capture proxy) or it silently runs on the main thread. This is the single most common footgun in this codebase.

## Architecture

Single-screen app driven by a phase state machine. `SnapStickApp` injects two `@MainActor ObservableObject`s as environment objects — `PhotoStore` (persistence) and `AppSettings` (config) — into `ContentView`, which owns everything else. They are injected onto a `RootView` wrapper (not `ContentView` directly): `RootView` observes `AppSettings` via `@EnvironmentObject` so theme/language changes re-run its `body` and re-apply `.preferredColorScheme` / `.environment(\.locale, …)` live. Applying those modifiers directly on `WindowGroup`'s child did **not** reliably re-apply on App-level `@StateObject` changes — that was the root cause of theme/language not switching without a restart.

> **Note:** The app is fully free with no limits and no developer options. An earlier "paper economy" (daily free-paper quota, paid membership, premium papers, share watermark) and a password-gated dev mode were deliberately removed — `QuotaStore`, `MembershipStore`, `PaperEconomy.swift`, `MemberUpsellView`, `PaperStyle.isPremium`, the share watermark, `AppSettings.devModeEnabled`/`devPassword`, and the film-counter wheel no longer exist. If you find references to those in old docs/commits, they are gone. All papers are free and switchable; every shot just works.

**`ContentView` is the orchestrator.** It holds the `StudioPhase` state machine and four `@StateObject` engines (`CameraController`, `MotionManager`, `SandboxEngine`, `SoundPlayer`) and wires their callbacks together. Read this file first to understand control flow.

### Navigation (bottom tab bar)

`ContentView`'s body is an **iOS 26 native `TabView`** with three icon-only tabs: 日历 (`calendar` → `CalendarView`), 拍照 (`camera.fill` → the studio, default) , 设置 (`gearshape.fill` → `UserCenterView`). Using the native `Tab { } label: { }` builder (not the old `.tabItem`, and not `.page` style) is what gives the floating **Liquid Glass** tab bar and its sliding-selection morph *for free* — do not hand-roll a glass bar with `GlassEffectContainer`; that was tried and removed. Trade-off accepted to get the native glass: **no swipe-paging between tabs and no raised center button** (the camera is just a normal tab).

- The nested selection enum is named **`Screen`** (not `Tab`) specifically to avoid colliding with SwiftUI's `Tab` type.
- The history `HistoryView` is a separate full page presented via `.fullScreenCover(isPresented: $sidebarOpen)` (back button, not a drawer). Global overlays (camera-permission, original-photo preview) sit in a `ZStack` *over* the `TabView` so they cover the tab bar too. Per-screen overlays (error/toast) live inside `studioLayer`.
- The camera session is owned by `ContentView`, so switching tabs never tears it down even though the studio view itself may be rebuilt.

### The capture pipeline (state machine)

`StudioPhase`: `idle → ejecting → developing → done` (defined in `Models.swift`).

On shutter, two async tasks run in parallel and a barrier merges them:
1. A fixed **eject animation** timer sets `ejectDone`.
2. The **Vision cutout** (`VisionCutout.cutout`) on the original photo sets `cutoutReady`.

`maybeDevelop()` only advances to `developing` once *both* `ejectDone` and `cutoutReady` are true — so the developing animation never outruns processing (the eject timer normally dominates, since the on-device cutout is sub-second). The cutout task also runs `SubjectClassifier.classify` on the cutout (or on the original, if no subject was found) before setting `cutoutReady`, so the classification fields ride on the committed `PhotoRecord`; classification is sub-second too. The finished `PhotoRecord` is held in `pendingPhoto` until `finishDevelop()` commits it to the store, stamps it with the current `selectedPaperID`, and spawns it into the sandbox. If no subject is found, the original photo is kept and an error toast shown — the flow always completes. There is **no quota or paywall** — `handleShutter()` only guards against an in-flight tear transition; every shot proceeds.

**Shake-to-develop (甩照片).** The `.developing` phase splits into a wait then a reveal: `maybeDevelop()` starts a **cancellable** `developTask` that sleeps `developWait` (~4s) and then calls `triggerReveal()`; `triggerReveal()` flips the `reveal` flag (driving the view's ~1s blur→clear animation) and, after `developReveal` (~1s), calls `finishDevelop()` — so a still phone develops in ≈5s. Shaking the phone mid-develop fires `MotionManager.onShake → handleShake()`, which cancels `developTask` and calls `triggerReveal()` immediately (with a haptic), cutting the wait so the print appears in ≈1s — mimicking shaking a Polaroid. `developShaken` de-dupes so one develop only accelerates once. The two paths (timer / shake) funnel through the single `triggerReveal()`; the reveal is triggered explicitly (`reveal` → `withAnimation`) rather than as an implicit duration-long animation, because re-targeting an in-flight implicit animation to the same value to "speed it up" is unreliable in SwiftUI. During the wait the photo window shows the emulsion "冲印中" scan animation plus a 摇一摇加速显影 hint; `reveal`/`developShaken`/`developTask` reset on each `beginShot`/`handleRetake`.

**Tear-to-burst continuous shooting (撕纸连拍).** Pressing the shutter while already in `.done` doesn't reset to `idle` first: `handleShutter` sets `tearing = true`, the finished print animates *down* into the sandbox and fades, then after a short delay `beginShot()` ejects the next print in place. `tearing` locks the shutter during the transition.

### Key components

- **`Models.swift`** — `PhotoRecord` is the core value type: `original` (shot), `result` (kept equal to `original` now that there is no AI render step), `cutout` (subject extracted, may be nil), `paperStyleID` (the applied paper style; appearance only, freely switchable), and the classification fields — `primaryCategoryID` (a `StickerCategory` raw id), `rawVisionLabel` + `rawVisionConfidence` (Vision's Top-1, kept verbatim for future re-mapping), `visionCandidates` (Top-5), and `categorySource` (`.vision` auto / `.user` manual override). `displayImage` returns cutout-or-result; `paperStyle` resolves the id through `PaperCatalog`. Images are held as `UIImage` in memory; `PhotoStore` handles disk.
- **`PhotoStore.swift`** — local persistence, no upload (matches the web app's privacy model). Images written to `Documents/SnapStickPhotos/` as jpg (original/result) and png (cutout); metadata in `index.json` (`Meta` includes an optional `paperStyleID` and `deletedAt` — both missing on old data, decode to nil). `setPaperStyle(_:styleID:)` re-stamps a record's paper without touching image files; `setPrimaryCategory(_:categoryID:)` re-stamps the primary category and marks `categorySource = .user`. Legacy data migrates on load: the old `category` string becomes `rawVisionLabel`, and a missing `primaryCategoryID` is derived from it via `StickerCategory.category(for:)`. Replaces the original Core Data + CloudKit scaffold, which was deleted.
  - **Recycle bin (soft delete).** `delete(_:)` is a **soft delete**: it stamps `deletedAt` and moves the record from `photos` to the published `trashed` array **without touching files**. `restore(_:)` clears the stamp and moves it back; `purge(_:)`/`emptyTrash()` are the only paths that actually remove files; `trashAll()` soft-deletes every active record (the history page's "清空所有记录"). **30-day auto-clear is lazy:** `load()` (run at app launch) purges any trashed record whose `deletedAt` is older than `PhotoStore.trashRetention` (30 days) — there is no background timer, so cleanup only happens when the app is next opened. `photos` holds `deletedAt == nil` records; `trashed` holds the rest, sorted by deletion time.
- **`VisionCutout.swift`** — on-device subject extraction via Vision's `VNGenerateForegroundInstanceMaskRequest` (iOS 17+; the same model behind Photos' "拷贝主体"). Runs the foreground-mask request on the original photo, masks to the subject (any background, no white needed), converts the masked `CVPixelBuffer` to a `CGImage`, downscales to a 512px work size, then paints a solid white die-cut border (CoreGraphics disk-offset silhouette, carried over from the old `ImageCutout`). Runs `nonisolated` on a detached task. Returns nil if no subject is detected.
- **`SubjectClassifier.swift`** — on-device subject classification (`VNClassifyImageRequest` + `VNRecognizeAnimalsRequest`), run right after the cutout; fully offline, no Doubao involved. Produces a `SubjectClassification`: a user-facing primary `StickerCategory` (10 fixed cases — 美食/饮品/花草/宠物/穿搭/美妆/家居/手作/出行/其他; rawValue is the stable persisted id), Vision's raw identifier + confidence, and the Top-5 merged candidates. An animal hit ≥ 0.30 forces `.pet`; otherwise the first `labelMap`-mapped label among the Top-6 image labels (≥ 0.15 confidence) wins, falling back to `.other`. `SubjectCategory.displayName(_:locale:)` maps raw identifiers to 中/EN display names with a humanize fallback. Returns nil when unsure — the record then stays 未分类. `docs/PRD-贴纸分类.md` is the PRD.
- **`AppSettings.swift`** — UserDefaults-backed config: sandbox `speed`/`sensitivity`, `developTime` (3–8s), motor/shutter sound toggles, `wallHitHaptic`, `appearance` (`AppearanceMode`: system/light/dark), and `language` (`AppLanguage`: system/zh-Hans/en); plus the Doubao trio — `doubaoAPIKey` (stored in the **Keychain** via `KeychainStore`, not UserDefaults), `doubaoModelID`, `doubaoBaseURL`, with `doubaoConfigured` as the completeness check. (No more dev mode — removed with the paid features.) `appearance.colorScheme` is applied app-wide via `.preferredColorScheme`, and `language.locale` via `.environment(\.locale, …)`, both in `SnapStickApp`. See **Internationalization** below.
- **`DoubaoAPI.swift` / `DoubaoSettingsView.swift` / `KeychainStore.swift`** — the optional bring-your-own-key Doubao layer (no app feature requires the key). `DoubaoAPI` is a minimal Volcengine Ark Chat Completions client (`sayHi`/`chat`, OpenAI-compatible wire format). `DoubaoSettingsView` (a sheet opened from the 设置 tab) edits key / model / endpoint and ends with a 「连接测试」 section — currently the **only caller** of `DoubaoAPI`: it sends "hi" and shows the model's reply verbatim on success, or a categorized failure (bad URL / HTTP code + server message / unparsable response / network error). Editing any field resets the test result; closing the sheet cancels an in-flight test. `KeychainStore` is a tiny generic-password Keychain wrapper, used only for the API key.
- **`PaperStyle.swift`** — the paper catalog (single source of truth, analogous to `Palette`). `PaperStyle` declares all visual params (mat gradient, border, caption ink, `PaperDeco` decoration); `PaperCatalog.all` holds 7 styles (all free), with a `style(for:)` accessor and `defaultID = "cream"`. Paper affects **only** the final framed output — never the Vision cutout, sandbox physics, or sound. Add/adjust paper here only.
- **`PaperFrameView.swift`** — the single rendering path for paper, used for both on-screen preview and off-screen export. `PaperMat` (gradient + centered sticker + `PaperDecoView` decoration) fills the photo window; `PaperFrameView` is the full card (border + square mat + date caption). `PaperRenderer.image(…, locale:)` rasterizes the card to a ~1080px `UIImage` for sharing, re-injecting `.environment(\.locale,)` (an off-screen `ImageRenderer` doesn't inherit the app environment). `ShareImage`/`ShareSheet` wrap the system share panel.
- **`PaperUI.swift`** — paper interaction UI. `PaperPickerSheet`: the bottom paper-picker grid (live thumbnails via `PaperFrameView`); every paper is directly selectable (no locks, no upgrade bar).
- **`Localization.swift`** — i18n infrastructure: the `AppLanguage` enum and the `localizedString(_:locale:)` runtime helper. See **Internationalization** below.
- **`CameraController.swift`** — AVFoundation live preview + grab-current-frame. Session config and the sample-buffer delegate run on background queues (`@unchecked Sendable` `FrameBox`/`SampleBufferProxy` bridge frames across threads); `@Published` UI state is published back on main. `captureSquare()` orients the sensor buffer for portrait (back = right, front = leftMirrored) and center-crops to square.
- **`StickerSandboxView.swift`** — the physics engine. `SandboxEngine` runs a `CADisplayLink` loop (`tick → simulate → publish`) doing gravity integration, wall bounce, and circle-circle collision resolution. Gravity direction comes from `MotionManager`; physics constants at the top mirror the web version. `sync(photoIDs:freshId:)` reconciles bodies with the visible photo list — the `freshId` body drops from the photo window, others scatter. The view itself is non-interactive (`allowsHitTesting(false)`).
- **`PolaroidStudioView.swift`** — the instant-camera UI (viewfinder, shutter, ejecting photo, multi-stage tear/eject animation, develop animation). The ejected print's vertical position and opacity are driven explicitly in code to chain "tear down → snap back to the slot → rise and fade in" for tear-to-burst. The develop reveal is gated on the `reveal` input (not the whole `.developing` phase): until `reveal` flips true the window shows the emulsion "冲印中" film + 摇一摇加速显影 hint (`developingFilm`); on `reveal` it runs a single explicit `withAnimation` blur→clear over `developDuration` (the reveal-animation length, ~1s — see shake-to-develop above), with `revealActive` reset on each `.ejecting`. The result print shows the current `paperStyle` via `PaperMat`, with a **paper-picker button in the photo window's top-right corner** (opens the bottom paper-picker sheet) and 下载/分享 actions below. **Tapping the photo itself toggles 贴图 ↔ 原图 in place** (local `showingOriginal` state crossfades between the paper-matted sticker and `photo.original`; reset to 贴图 on each new `.ejecting`) — a small 贴图/原图 capsule in the bottom-left corner just *indicates* the current state (non-interactive). This replaced the old full-screen original-photo modal, so `onViewOriginal` / `ContentView`'s `originalPreview` overlay is now dead code (left in place). Note: file/struct name still says "Polaroid" but the visual design was deliberately changed to avoid Polaroid trademark/trade-dress (see design notes below).
- **`MotionManager.swift`** — CoreMotion gravity vector feeding the sandbox. The same `deviceMotion` callback also does **shake detection**: when `userAcceleration` magnitude crosses a threshold (with a 0.4s debounce keyed off `motion.timestamp`, not `Date`) it fires the `onShake` callback, which `ContentView` wires to `handleShake()` to accelerate the develop (see the shake-to-develop note above).
- **`StickerDetailView.swift`** — the sticker detail sheet (drag-dismissable, with detents), opened from the calendar day view, the 贴纸册 (history) list, the studio's finished card, and the sandbox. A horizontal pager swipes through the group of stickers determined by the entry point (history = the current filtered list, calendar = that day, sandbox = visible stickers, studio = all history). Per page: the framed card (tap toggles 贴图/原图), meta info, a **category panel** (changing the primary category calls `onPickCategory` → `PhotoStore.setPrimaryCategory`, stamping `categorySource = .user`; the raw Vision label is never touched), and a paper strip; fixed bottom 保存/分享/删除 actions.
- **`HistoryView.swift` / `CalendarView.swift`** — history (UI name 贴纸册) as a standalone full page (pushed via `.fullScreenCover`, dismissed with its top-left back button) and calendar browse of past stickers. The history page is opened both from the studio header and from the 设置 tab; it has a **category filter bar** (全部 / each category present / 未分类 — the whole bar hides when nothing is categorized), and rows open `StickerDetailView`. `ConfirmOverlay` (the reusable delete/clear dialog) also lives in `HistoryView.swift`. Delete and "清空所有记录" are now **soft** (they move stickers to the recycle bin, recoverable for 30 days), so neither needs the typed "我确认" gate anymore — that gate moved to `RecycleBinView`'s empty-bin action.
- **`RecycleBinView.swift`** — the recycle bin, a standalone full page (`.fullScreenCover`) opened from the 设置 tab. Lists `PhotoStore.trashed` (each row: thumbnail + "X 天后自动清空" remaining + 恢复 / 彻底删除), with an empty state and a bottom "清空回收站" gated by the typed "我确认" confirmation (the one truly-unrecoverable action). Reuses `ConfirmOverlay`. Remaining-days are computed from `deletedAt` against `PhotoStore.trashRetention`.
- **`UserCenterView.swift`** — the 设置 tab (a settings hub; there is no user/login concept despite the file name). Shows work stats (total / this-month / active-days) and a settings list: theme appearance (inline segmented `Picker` bound to `settings.appearance`), 界面语言 (inline segmented `Picker` bound to `settings.language` — 跟随系统/中文/English), 豆包 API (opens `DoubaoSettingsView` as a sheet; subtitle reflects `doubaoConfigured`), 交互设置 (opens `SettingsView` as a sheet), 贴纸册 (opens `HistoryView` as a full page), 回收站 (opens `RecycleBinView`; subtitle shows the pending count via `trashedCount`), and an about card.
- **`SettingsView.swift`** — the 交互设置 sheet presented from `UserCenterView`: sound toggles (马达 / 拍照), the 显影时间 slider (`developTime`, 3–8s), and 贴纸物理 (`speed`/`sensitivity` sliders plus the 边缘碰撞震动 haptic toggle). App-wide settings (theme/language/Doubao) live in `UserCenterView` directly.
- **`SoundPlayer.swift`** — shutter/motor sound effects and haptics.

## 相纸 (Paper) styles

A fully **local, no-backend, no-account** layer (mirrors the privacy model). Paper is **appearance only** — purely a framing style, with no quota, paywall, or membership.

- **Paper styles (`PaperStyle`/`PaperCatalog`)** — 7 border/mat/decoration looks, all free. They never affect the cutout, physics, or sound. Switchable any time after the shot (in the result page or picker); the choice persists per-record (`PhotoRecord.paperStyleID`, via `PhotoStore.setPaperStyle`) and the last-used style is remembered in UserDefaults (`paper.lastStyle`).
- **Framed sharing (`PaperRenderer` → `ShareSheet`)** — composites sticker + selected paper + date into one image for the system share panel (no watermark).

All new paper colors must come from `Palette`; don't hardcode literals. (`docs/PRD-相纸功能.md` is the original PRD and predates the removal of quota/membership — treat it as historical.)

## 贴纸分类 (Sticker categories)

Two-layer, fully on-device (Doubao is **not** part of this — see the Doubao note at the top):

- **Primary category** (`StickerCategory`, 10 fixed ids) — the only layer users see: shown on cards, filterable in 贴纸册, editable in the detail sheet. Auto-recommended by `SubjectClassifier` after each shot (`categorySource = .vision`); a manual change stamps `.user` and is never auto-overwritten.
- **Raw Vision labels** (`rawVisionLabel` + confidence + Top-5 `visionCandidates`) — Apple's technical identifiers, persisted verbatim for future re-mapping / recommendation; never used directly as filter chips. Changing the primary category leaves them untouched.

Old records migrate lazily in `PhotoStore.load()` (legacy `category` → `rawVisionLabel` + a mapped primary). `docs/PRD-贴纸分类.md` is the PRD.

## Design constraints (do not regress)

Colors live **only** in `Palette.swift`. Change colors there; views reference the palette, never raw literals.

**Theme colors (the two signature colors):**
- **Klein blue `#002FA7`** (`klein`) — the primary signature accent (machine body, rings, share button), over a warm paper (手帐/journal) palette.
- **Cadmium yellow `#FDD835`** (`cadmium`) — the secondary signature color, used for the shutter dot. The blue↔yellow contrast (蓝黄撞色) is the brand's core color pairing.

Two kinds of tokens:
- **Fixed brand colors** — `klein`, `kleinDeep`, `cadmium`, `amber`, `cream`, `kraft`, `faceplate`, and `ink` (note: `ink` is now used as a fixed *shadow* color, it does not follow the theme).
- **Dynamic semantic colors** that adapt to light/dark via `Palette.dynamic(light:dark:)` (a `UIColor` trait closure): `surface` (full-screen background), `card` (panel/card fill), `chip` (secondary fill — placeholders, small round buttons), `label` (primary text/icon). **Use these for any new chrome so it tracks the theme** chosen in 设置; don't hardcode `.white`/`Color(white:)`.

The camera was deliberately redesigned away from looking like a Polaroid to avoid trademark/trade-dress risk. **Do not reintroduce**: the 5-color rainbow spectrum stripe (a Polaroid registered trademark), the red round shutter, or the white-box + big-round-lens + rainbow-stripe look. Square photos with thick white borders are kept (generic, low risk).

## Internationalization (中英文)

The app is bilingual — **Chinese (zh-Hans, the source language) and English (en)**. It follows the system language by default, and the user can override it in-app (设置 → 界面语言: 跟随系统 / 中文 / English). Switching is **live, no restart**.

**How it works:**
- **Source language is Chinese.** UI strings stay written as their Chinese original in code (`Text("冲印中")`); the Chinese text *is* the lookup key. English translations live in **`SnapStick/Localizable.xcstrings`** (a String Catalog), permission strings in **`SnapStick/InfoPlist.xcstrings`**. `developmentRegion = zh-Hans`; `knownRegions` includes `en` + `zh-Hans`. Both catalogs are auto-compiled by the synchronized file group (don't hand-edit `project.pbxproj` to register them).
- **Display path = SwiftUI `LocalizedStringKey` + environment locale.** `SnapStickApp` injects `.environment(\.locale, settings.language.locale)` at the root. Every `Text("中文")` literal (and `Section`/`Button`/`navigationTitle`/`.accessibilityLabel(Text(…))`) resolves against that locale, so changing `settings.language` re-localizes the whole tree instantly. This is why most views needed **no change** beyond having the right catalog entry.
- **String-returning helpers must be typed `LocalizedStringKey`, not `String`.** `Text(someString)` is *verbatim* (not localized) — that's the main footgun. So error/toast state in `ContentView`, `shutterHint`, `AppearanceMode.labelKey`, `PaperStyle.displayName`, `ConfirmOverlay`'s title/message/label, and the `menuRow`/`statCard` helper params are all `LocalizedStringKey`. To localize a *runtime* string (e.g. a paper name), wrap it: `Text(LocalizedStringKey(style.name))`.
- **Two things can't ride the environment locale**, so they take an explicit `Locale` (read via `@Environment(\.locale)` and threaded through):
  1. **Dates / weekday symbols** — `DateFormatter`/`Calendar` aren't SwiftUI. Use `f.locale = locale` + `setLocalizedDateFormatFromTemplate(…)` (never a hardcoded `"yyyy年M月d日"` pattern or `Locale(identifier: "zh_CN")`), and `Calendar.veryShortWeekdaySymbols` for weekday letters. See `PolaroidStudioView.dateString(_:locale:)`, `CalendarView`, `HistoryView`.
  2. **Off-screen `ImageRenderer` (share image)** — doesn't inherit the app environment, so `PaperRenderer.image(…, locale:)` re-injects `.environment(\.locale, locale)` onto the rendered card.
- **Runtime String lookups that must honor the in-app override** (not the system language) go through **`localizedString(_ key:locale:)`** in `Localization.swift`, which loads the matching `.lproj` bundle directly. Used for the date-group labels (今天/昨天) and the clear-history typed-confirmation gate (输入「我确认」 / type "I confirm") — the gate compares against `localizedString("我确认", locale:)` so the required word matches the displayed language. `String(localized:)` is **avoided**, since it follows the system language, not `settings.language`.

**Adding a new user-facing string:** write it in Chinese in code as usual, then add the key (Chinese original) + its `en` translation to `Localizable.xcstrings`. If it's shown via a `String`-typed value rather than a literal, make that value `LocalizedStringKey`. If it's a date, format it with the environment `locale`. Permission strings go in `InfoPlist.xcstrings` (those always follow the **system** language — the OS shows them, so the in-app override can't affect them).
