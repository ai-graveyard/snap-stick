# 拍立贴 (SnapStick) — 产品需求文档

> 本文档描述拍立贴当前已实现的产品形态与功能，与代码保持同步。

## 1. 产品概述

拍立贴是一个网页应用，模拟拍立得（Polaroid）相机的拍照体验。用户通过摄像头「拍摄」当前场景，相纸以拍立得的方式从机身底部吐出并逐渐显影，最终呈现的不是原始照片，而是一张 AI 生成的**卡通贴纸**（die-cut sticker 风格）。生成的贴纸会被**抠掉背景**变成一张单独的模切贴纸，再像一个有弹性的实体小物件一样从高空**弹跳掉落进屏幕底部的收集托盘**——整体营造一种「一张一张收集小贴纸」的把玩感与收集欲。

**核心体验流程：**
```
[拍立得相机居中取景] → 按下快门 → [白闪 + 快门声]
    → [相机整体上移] + [相纸从底部出纸口吐出，空白药膜 + 扫描线，出纸马达声]
    → [等待 AI 返回，期间相纸停在画面中上方]
    → [出纸动画与 AI 都就绪后，贴纸图片在约 3 秒内从模糊渐变到清晰]
    → [显影完成：抠好背景的单独贴纸从高空弹跳掉落进底部收集托盘]
    → [展示最终结果 + 日期 + 重拍/保存按钮，托盘里多出一张收藏]
```

## 2. 用户故事

- 作为一个用户，我想通过网页调用摄像头，点击按钮（或按空格键）「拍」一张照片
- 作为一个用户，我想看到相纸像拍立得一样从机身吐出、慢慢显影，而不是瞬间出现
- 作为一个用户，我想最终看到一张有趣、可爱的卡通贴纸，而不是原始照片
- 作为一个用户，我想贴纸是抠掉背景的「单独贴纸」，而不是一整张方形图片
- 作为一个用户，我想每拍一张，贴纸就像实体小物件一样弹跳着掉进收集托盘，慢慢攒成一排
- 作为一个用户，我想在历史记录里查看所有拍过的贴纸
- 作为一个用户，我想把最终生成的贴纸保存/下载到本地
- 作为一个用户，我想点击历史记录重新查看某张贴纸
- 作为一个没有摄像头/未授权的用户，我想用 demo 模式也能体验完整动画

## 3. 功能需求

### 3.1 摄像头拍照
- 页面加载后自动请求摄像头权限，**优先后置摄像头**（`facingMode: environment`），失败时回退前置摄像头
- 摄像头实时画面渲染在拟物拍立得相机的「镜头」里
- 用户点击红色快门按钮（或在桌面端按下空格键）触发拍照
- 拍照瞬间有快门视觉/听觉反馈（白闪 + 快门声）
- 拍照时用 Canvas 对视频帧做**居中正方形裁剪**，导出为 JPEG（质量 0.9）
- **权限/异常处理**：对被拒绝、无设备、被占用、非安全上下文、未知错误分别给出中文提示；可重试场景提供「允许使用摄像头」按钮
- **Demo 模式**：URL 带 `?demo=1` 时用 Canvas 合成的动态渐变画面代替摄像头，便于演示和调试动画

### 3.2 拍立得相机与出纸动画

**布局基础：** 全屏暗色摄影棚背景（径向渐变），画面中央渲染一台拟物拍立得相机 —— 顶部黑色取景脑门 + 取景器 + 闪光灯、中间大圆镜头（内嵌摄像头实时画面）、经典彩虹条、底部红色快门按钮与出纸口。相纸位于相机之后，初始藏在机身内。

**动画流程（拍照后），由状态机 `idle → ejecting → developing → done` 驱动：**
1. **白闪** + 快门声
2. **ejecting**：相机 + 相纸整体上移（约 -42%），相纸从底部出纸口往上吐出（约 2 秒），伴随出纸马达声
3. 相纸图片区域初始为**空白药膜**，有扫描线动效和「冲印中」文字
4. **等待 AI 返回**，期间相纸停在画面中上方
5. **developing**：当「出纸动画完成」与「AI 返回」两个信号都就绪后进入显影，图片内容在约 3 秒内从 `blur(16px) + 偏暗 + 低饱和` 渐变到清晰
6. **done**：相纸底部白边显示拍摄日期 + 重拍/保存按钮

**音效：** 快门声与出纸马达声均由 Web Audio API 实时合成（振荡器 + 增益包络），无需任何音频素材文件。

**重拍流程：** 点击重拍 → 状态回到 `idle`，相纸滑回机身、回到取景状态。

### 3.3 AI 生成贴纸（核心功能）
- 拍照后**立即在后台并行调用** AI（不阻塞出纸/显影动画）
- **贴纸风格定义：** 保留照片主体特征，转成简洁明快的卡通插画风格，加粗白色描边轮廓（die-cut sticker），明快配色、纯白背景，类似聊天表情贴纸
- 生成完成后，相纸从「空白药膜」过渡到 AI 贴纸的显影动画
- 若 AI 比出纸动画慢（常见），相纸会保持「冲印中」直到结果返回再开始显影
- **失败兜底**：AI 生成失败时保留原始照片，提示「贴纸生成失败，已保留原图」，该记录仍写入历史

**使用的 AI 模型：** 豆包 `doubao-seedream-5-0-260128`（火山引擎方舟 / Volcengine Ark）
- 类型：图生图编辑模型，将照片主体转换为卡通贴纸风格
- 单次任务耗时：约 20~35 秒（前端设置 60 秒超时）
- 输出尺寸：`2K`，带水印
- **提示词约束：** 要求纯白背景纯色平涂、主体居中且四周留白不触碰画面边缘 —— 为后续前端抠图提供干净、可分离的背景

### 3.7 抠图与收集托盘（核心玩法）

**抠图（去背景）：**
- AI 返回白底贴纸后，前端用 canvas 把背景抠掉，得到一张透明背景、四周带白色模切边的**单独贴纸**
- 实现要点（`src/lib/cutout.ts`，纯前端、不依赖额外服务）：
  1. 取四角平均色作为背景色（容忍轻微偏色/压缩噪点）
  2. 从图片四条边做**洪水填充**，只移除「与边缘相连且接近背景色」的像素 —— 因此主体内部的白色细节（高光、衣物等）会被保留，不会误删
  3. 边界像素按到背景色的距离做 alpha 羽化，减少白边毛刺
  4. 裁切到主体外接框，让贴纸轮廓紧贴主体
  5. 在主体外补一圈实心白色模切描边，做出贴纸质感
- 抠图失败（如背景不够干净）时回退为整张贴纸，保证流程不中断

**收集托盘（弹跳掉落 + 收集）：**
- 屏幕底部常驻一个收集托盘，横向陈列所有收藏的贴纸，每张带轻微随机倾角，营造「随手贴上去」的随意感
- **掉落动画**：显影完成的那一刻，新贴纸从接近屏幕顶部的高空落下，带挤压回弹（squash-and-stretch）的弹跳，落定在托盘里，像一个有弹性的实体小物件
- 托盘里贴纸超出宽度时可横向滚动
- 点击托盘里的任意贴纸可直接查看（复用历史查看逻辑，跳过显影动画）
- 托盘为空时显示引导文案「拍一张，收集你的第一个贴纸」

### 3.4 最终展示
- 最终状态：一张放在拍立得相纸上的卡通贴纸图片（正方形画面）
- 相纸底部白边显示拍摄日期（zh-CN 长日期格式）
- 提供「重拍」与「保存」按钮

### 3.5 历史记录列表
- 顶栏左上角按钮打开左侧抽屉式历史记录面板（带遮罩，移动端优先）
- 以 2 列网格展示所有历史贴纸，每条显示缩略图，hover/触摸显示拍摄时间
- 面板标题处显示记录总数
- 点击某条记录可**跳过动画直接查看**该贴纸大图
- 历史记录按时间倒序排列（最新在最上面）
- 提供「清空所有记录」按钮
- 数据存储在浏览器 IndexedDB，**不设数量上限**

### 3.6 保存与分享
- 提供「保存」按钮，将最终贴纸（优先抠好背景的透明 PNG）下载到本地，文件名为 `snapstick-{timestamp}.png`

## 5. 技术方案

### 5.1 技术栈
- **框架：** Next.js 14（App Router）+ TypeScript
- **前端：** React 18 + Tailwind CSS 3
- **动画：** Framer Motion + CSS keyframes（扫描线等）
- **音效：** Web Audio API（实时合成，无素材文件）
- **摄像头：** `getUserMedia` API
- **拍照：** Canvas 截取并居中裁剪视频帧
- **状态管理：** React hooks（`useState` / `useCallback` / `useEffect` 状态机）
- **本地存储：** IndexedDB（存储照片 base64 数据）
- **后端代理：** Next.js API Route (`/api/generate`)

### 5.2 AI 图像生成

**使用的 API：** 火山引擎方舟（Volcengine Ark）图像生成接口
- Endpoint：`https://ark.cn-beijing.volces.com/api/v3/images/generations`
- 鉴权：`Authorization: Bearer {ARK_API_KEY}`
- 模型：`doubao-seedream-5-0-260128`
- 请求参数：`prompt`、`image`（base64）、`response_format: "url"`、`size: "2K"`、`watermark: true`、`stream: false`
- 单次任务耗时：约 20~35 秒

**后端代理（Next.js API Route）：**
```
# src/app/api/generate/route.ts
POST /api/generate
Body: { image: base64DataURL, prompt: string }
→ 服务端读取 ARK_API_KEY，转发到方舟图像生成接口
→ 取回图片 URL 后，服务端下载并转 base64（规避跨域/防盗链）
→ 返回 { image: "data:image/...;base64,..." }
```

**前端调用流程：**
```
前端 (base64 图片) —— src/lib/api.ts: generateSticker()
  │
  ▼ POST /api/generate（60s 超时，AbortController）
Next.js API Route（服务端）
  │  读取环境变量 ARK_API_KEY
  ▼
  │  POST https://ark.cn-beijing.volces.com/api/v3/images/generations
  │  model: doubao-seedream-5-0-260128
  ▼
方舟 / 豆包 API
  │
  ▼ 返回图片 URL
Next.js API Route（下载图片 → 转 base64）
  │
  ▼ 透传 { image }
前端 → 写入 IndexedDB → 更新历史记录
```

**API Key 安全：**
- `ARK_API_KEY` 存储在服务端环境变量（`.env.local`），仅 API Route 可读，前端不可见
- 前端始终经 `/api/generate` 调用，不直接接触 Key

### 5.3 数据存储

存储于 IndexedDB（数据库 `pai-li-tie-db`，对象仓库 `photos`，主键 `id`）。每条记录为一个 `PhotoRecord`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | `crypto.randomUUID()` 生成 |
| `originalImage` | string | 原始拍摄照片（base64 data URL） |
| `resultImage` | string | AI 生成的整张白底贴纸（base64 data URL；失败时回退为原图） |
| `cutoutImage` | string? | 抠掉背景后的单独贴纸（base64 PNG，透明 + 白色模切边；抠图失败时缺省） |
| `timestamp` | number | 拍摄时间戳 |

## 6. 已确认的需求细节

1. **AI 模型：** `doubao-seedream-5-0-260128`（豆包 / 火山引擎方舟）
   - Endpoint：`https://ark.cn-beijing.volces.com/api/v3/images/generations`
   - 图生图编辑模型，将照片主体转为卡通贴纸/die-cut sticker 风格
   - 单次任务约 20~35 秒，返回图片 URL，服务端代理下载后转 base64
2. **显影动画：** 相机居中取景 → 拍照后相机上移 → 相纸从底部出纸口吐出 → 空白药膜等待 AI → 出纸与 AI 都就绪后约 3 秒渐显
3. **抠图 + 收集：** AI 白底贴纸经 canvas 抠掉背景成单独贴纸 → 显影完成后从高空弹跳掉落进底部收集托盘 → 横向陈列、点击查看，营造收集小物件的把玩感
4. **拍照即时反馈：** 白闪 + 快门声 + 出纸马达声（Web Audio 实时合成）
5. **历史记录：** 不设上限，全部存在 IndexedDB；点击历史可跳过动画直接查看
6. **移动端适配：** 以手机为主，优先后置摄像头，安全区适配，禁用橡皮筋滚动/双击缩放；桌面端支持空格键拍照
7. **Demo 模式：** `?demo=1` 用合成画面代替摄像头
8. **无登录：** 纯匿名使用，照片仅存在浏览器本地
